# Checkpoint M2 — The QA Desk

Tag: `checkpoint-m2` (main `d8e940f`). Issues: #27, #28, #29, #34 (gate fix), #30.

## What was built
- **QA desk in the sim:** every product queues at the desk (cap 8); ship/reject; defects come from sloppy bots, plus harmless decoys; shipped defects become complaints (score penalty); a full queue backs up the line; idle metric.
- **Desk screen:** bottom strip with queue, large product under a lamp (5 defect types, 3 decoys, bot flair), ✖/✔ buttons + swipe + ←/→ keys, stamp/drop tweens, BRB sign, streak, flashes, day-1 hint. HUD shows complaints and score vs target.
- **Balance:** data-only tuning (#29), plus a second pass (#34) for the simultaneous-fault gate the first checkpoint run caught.

## Known issues
- **Careful ≈ greedy.** Same medians, idle and complaints; the careful player only differs in queue-full rate (16% vs 29%). Player choices don't yet change outcomes much.
- Careers end almost only on `sloppy` (≈ 95% of failed shifts): the QA desk dominates, machine faults rarely decide a day.
- Complaints sit at 0.57, close to the 0.5 floor.
- `factory.gd` is 502 lines; M3 sim work should add new files rather than grow it.

## Playtest feedback (folded into M3)
- #35 **No reference for a good product.** → M3-01 spec card + "why was that wrong" flashes + missed-defect list.
- #36 **Factory + desk on one screen is overload.** → M3 is rebuilt around two screens: a calm **QA office** (desk, spec card, wall monitor of machine lights, bots "calling in") and the **factory floor** (full screen). Going between them costs `transition_seconds` (~0.8 s); this replaces the walking worker.
